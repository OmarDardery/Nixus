# Reliability, UI and complexity audit

Reviewed base: `89747c685c576d63e2004dbf8425f5132aabea91` (main).
Date: 2026-11-23 (Africa/Cairo).

This is a source review with unit, static-analysis and browser-fixture validation.
It does not qualify a physical installation, prove disaster recovery or guarantee
absence of failures. Nixus remains a single-host beta.

## Findings repaired

| Priority | Failure | Repair / evidence |
| --- | --- | --- |
| High | App deletion ignored inventory errors, so unavailable Incus could be treated as absence and app source/recovery records removed. | Require a successful, correctly shaped complete Incus project inventory before removing source; retain ownership checks. Tests cover unavailable, malformed, empty, owned and unowned inventories. |
| High | First-load failures in Apps, Backups and Overview could redraw into another immediate request indefinitely. | Stop automatic first-load retries after failure; offer explicit retry and loading/error states. Never label unavailable Apps inventory as an empty server. Failure-recovery tests exercise redraws after rejection. |
| Medium | Each Incus API call created a new HTTP transport, leaving its idle socket/pool behind. | Reuse a bounded transport with an idle timeout. An HTTP fixture checks that repeated requests reuse one connection. |
| Medium | Rejected login attempts continued growing the failure slice and extending lockout; address entries never expired globally. | Keep five attempts per address, expire old entries, cap tracked addresses at 1024. Tests cover saturation, expiry and recovery. |
| Medium | Reaching the session limit discarded every existing session. Concurrent eviction could also make the login response dereference a missing session. | Expire old sessions and evict one least recently used session at the 128-session limit; return the authenticated admin role directly. Logout removes the session under the lock rather than mutating its creation timestamp. |
| Medium | One-click host update tried confirming with the pre-activation session, contrary to the server's fresh-login requirement. | Stop at activation and open Changes with the reconnect/sign-in instruction. Preserve the server's confirmation gate. The regression test now expects this handoff. |
| Medium | A slow poll could overlap later timer ticks; background redraws could interrupt typing. | Serialize status polls, defer their redraws while editing and retain a pending redraw until editing finishes. Avoid background Backups/repository/secret-inventory redraws while a form control is focused. |
| Medium | Linux usernames beginning with an underscore could sign in but fail the broker's audit-actor validation. | Share the Linux account name validator with audit identities. |

| Low | Mobile tables hid headers and presented unlabeled stacks; desktop overflow could be clipped. | Retain semantic tables and headers with horizontal scrolling. Move focus to main content on explicit navigation. |

## Dead code and unnecessary complexity

Removed the production-unreachable `restoreIncus` wrapper; its tests now target
the production preflight directly. Removed unused recovery candidate reads,
dummy import references in five files, and the obsolete drawer handlers and
sidebar/drawer CSS. Fixed all findings reported by Staticcheck without adding
runtime dependencies.

Keep the guarded review/apply/confirm workflow, source hashes, ownership checks,
backup consistency grouping and separate root broker. These protect distinct
failure boundaries and are justified complexity. Incus, PAM, restic and Git
already own their respective runtime, identity, backup and repository functions;
this change introduces no replacement framework or competing state store.

Further maintainability work should consolidate the remaining historical CSS
layers and replace the `untitled()` HTML-regex composition with renderers that
accept an explicit title option. Do that with visual coverage across every
merged Settings page, rather than combining it with host-state changes.

## Remaining failure boundaries

- A single server, its disks, power, router and network remain single points of
  failure. Off-host restic backups and a tested cold restore are required;
  successful export or metadata verification alone is not restore proof.
- No Nix executable or reference NixOS/Incus host was available here. The full
  flake evaluations, packaged build, NixOS VM tests, fresh installation,
  activation/rollback interruption, TLS and physical restore must pass in CI
  and the existing commissioning process before deployment qualification.
- Deletion is a multi-step operation, not an atomic transaction across Git,
  workspace files and Incus. Later cleanup failures can still require manual
  inspection/retry; local record removals and certificate cleanup currently
  contain best-effort error handling. Keep off-host backups.
- Background rendering avoids interruption while a form control has focus;
  this is not general persistence of every unfinished form across navigation,
  refresh or sign-out. Staged host settings and app drafts have their own
  explicit state/save paths.
- `docs/dev/architecture.md` still includes historical test paths and server
  timeout descriptions from an older implementation. Use the current workflow
  and Go server source as the evidence for executed checks and limits.
